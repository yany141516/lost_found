一、接口设计总说明
1.1 接口设计概述

本系统后端接口采用 RESTful API 设计风格，通过 HTTP 协议与前端进行数据交互。
接口统一使用 JSON 作为数据交换格式，采用标准 HTTP 方法（GET / POST）表示不同操作类型。

接口设计遵循以下原则：

接口路径清晰，语义明确

数据格式统一，便于前后端协作

功能模块划分清楚，便于维护与扩展

系统接口主要分为以下模块：

用户模块接口

失物信息模块接口

管理员模块接口

留言模块接口

二、用户模块接口说明
2.1 用户注册接口
接口说明

用户通过该接口完成账号注册。
系统对用户输入信息进行合法性校验，并对用户密码进行加密存储，避免明文保存。

接口信息
项目	内容
接口名称	用户注册
接口路径	/api/user/register
请求方式	POST
请求格式	application/json
是否需要登录	否
请求参数
参数名	类型	是否必填	说明
username	String	是	用户名
password	String	是	登录密码
contact	String	是	联系方式
请求示例
{
  "username": "testuser",
  "password": "123456",
  "contact": "13800001111"
}

返回示例
{
  "message": "注册成功",
  "user_id": 1
}

2.2 用户登录接口
接口说明

用户通过用户名和密码登录系统，系统对用户身份进行校验，并返回用户角色信息。

接口信息
项目	内容
接口名称	用户登录
接口路径	/api/user/login
请求方式	POST
请求格式	application/json
是否需要登录	否
请求参数
参数名	类型	是否必填	说明
username	String	是	用户名
password	String	是	登录密码
返回示例
{
  "message": "登录成功",
  "user_id": 1,
  "username": "testuser",
  "is_admin": false
}

三、失物信息模块接口说明
3.1 失物信息发布接口
接口说明

登录用户可通过该接口发布失物或拾物信息。
系统默认将信息状态设置为 “待审核”，由管理员进行后续审核。

接口信息
项目	内容
接口名称	信息发布
接口路径	/api/item/publish
请求方式	POST
请求格式	application/json
是否需要登录	是
请求参数
参数名	类型	是否必填	说明
user_id	Integer	是	发布用户 ID
item_name	String	是	物品名称
category	String	是	物品类别
item_type	String	是	丢失 / 拾获
location	String	是	发生地点
event_time	String	是	发生时间
description	String	否	物品描述
返回示例
{
  "message": "信息发布成功，等待管理员审核",
  "item_id": 1
}

3.2 失物信息查询接口
接口说明

该接口用于查询系统中 已审核通过（已发布） 的失物信息，支持条件筛选。

接口信息
项目	内容
接口名称	信息查询
接口路径	/api/item/list
请求方式	GET
是否需要登录	否
查询参数（可选）
参数名	说明
category	按物品类别查询
item_type	按丢失 / 拾获类型查询
返回示例
[
  {
    "item_id": 1,
    "item_name": "黑色雨伞",
    "category": "其他",
    "item_type": "丢失",
    "location": "教学楼A101",
    "event_time": "2025-03-01 14:30:00",
    "publish_time": "2025-03-01 15:00:00",
    "user_id": 1
  }
]

四、管理员模块接口说明
4.1 管理员审核接口
接口说明

管理员对用户提交的失物信息进行审核操作，决定信息是否发布，并记录审核结果。

接口信息
项目	内容
接口名称	信息审核
接口路径	/api/admin/audit
请求方式	POST
是否需要管理员	是
请求参数
参数名	类型	说明
admin_id	Integer	管理员 ID
item_id	Integer	失物信息 ID
result	String	通过 / 驳回
reason	String	审核原因（可选）
返回示例
{
  "message": "审核完成",
  "item_id": 1,
  "result": "通过",
  "current_status": "已发布"
}

五、留言模块接口说明
5.1 留言发布接口
接口说明

用户可在已发布的失物信息下进行留言交流。

接口信息
项目	内容
接口名称	留言发布
接口路径	/api/comment/add
请求方式	POST
是否需要登录	是
请求参数

5.2 留言查询接口
接口说明

查询指定失物信息下的所有留言记录。

接口信息
项目	内容
接口名称	留言查询
接口路径	/api/comment/list
请求方式	GET
查询参数

]

六、功能模块实现说明（总结性说明）

系统后端共实现用户管理、失物信息管理、管理员审核及留言交互四个核心功能模块。
各模块之间通过 RESTful API 进行通信，接口职责清晰，结构合理。

系统通过审核机制保障信息真实性，并通过留言功能增强用户之间的沟通效率，整体实现了校园失物招领业务的完整流程。
